# LCU 0.8.1

This release hardens the Linux in-place install and makes approval mode and the Chrome plugin copy safer. It adds no new harness verification claims and no new tested app pairs; Windows remains deferred.

## Changes

- **Stricter app ownership validation (Linux).** LCU validates the app it uses in place, and it now checks everything the desktop account executes: the runtime executables and modules, the directories above them, the complete CUA runtime tree and the complete Chrome, browser and computer-use plugin trees, including the scripts `lcu browser install` and `lcu browser status` run. Symlinks inside those trees are followed: a link may only point inside the app, and its target and the target's contents are validated too (a link that leaves the app is refused, and link cycles are handled). Group write counts only when every account in that group is trusted, instead of trusting group 0 by number, and POSIX ACL entries that give another user or group write access are refused where Linux exposes them (`system.posix_acl_access`). Group membership comes from the local account database and ACLs from that attribute, so members from a directory service are not seen. A read-only mount is checked like any other tree, because another account could write through a writable view of the same source. A root-owned package install, including `/usr/lib/chatgpt` and root-owned read-only mounts such as `/opt/silo/chatgpt/<version>-<arch>`, still passes.
- **Chrome plugin copy refresh.** The private copy of the original Chrome plugin that `lcu browser install` keeps now follows the selected app's plugin content, so an in-place app upgrade at the same path no longer leaves an old installer or native host. Refreshes are serialized with a lock, stage the copy and its digest, publish by rename and recover an interrupted refresh on the next run. The digest file is replaced rather than written through, so a symlink at that name can no longer redirect the write. **Copies made by 0.8.0 have no matching digest, so `lcu browser status` shows the connector as outdated until you rerun `lcu browser install`.**
- **Changed-since-install warning.** `lcu status` and `lcu doctor` warn when the app version or runtime on disk differs from the pair recorded at install. Stop agents before upgrading the ChatGPT package and restart them afterwards.
- **Approval reversal restores only LCU's changes.** `lcu setup --approval auto` now records what it changed (per config path, Oh My Pi profile and scope, and the previous Codex value) in `~/.local/state/lcu/approval.json`, and `--approval ask` reverses exactly that. An `mcp__lcu` rule or Oh My Pi `allow` entry that was already there is no longer removed, and a Codex `default_tools_approval_mode` you had set is restored instead of lost (and preserved across setups that do not use `auto`). Entries written by 0.8.0's `auto` have no record, so `ask` leaves them; remove them by hand. The uninstall steps now begin with the ownership-aware `--approval ask` reversal. See [approval mode](../INSTALLATION.md#approval-mode) and [uninstall](../INSTALLATION.md#uninstall).
- **`lcu prune` keeps app generations a kept release still uses.** A release installed with `--existing-app` pointing into `<prefix>/apps/<generation>` (a copy left by 0.7.0 or earlier) is now counted as using that generation, so pruning the older release no longer deletes the current app.
- **Read-only mount gate.** `tests/run.sh` now also installs LCU with `--existing-app` against the official app mounted read-only at `/opt/silo/chatgpt/<version>`, runs the desktop suite as the target account and follows a move to a different version folder.

## Gates

- `tests/run.sh` passed in disposable Linux ARM64 (native) and AMD64 (emulated) containers against the pinned ChatGPT 26.915.31945 package: 306 Python tests, offline in-place installation, agent registration, the exported MCP contract, the original GTK desktop suite with its independent save oracle, and the read-only mount gate (install at `/opt/silo/chatgpt/<version>`, desktop suite as the unprivileged account, reinstall at a second version folder, prune). The same gate also passed on both architectures against the official 26.928.31416 packages (SHA-256 values in the 0.8.0 notes), re-run to confirm the stricter validation accepts the real app tree.
- The adapter suite passed 36 tests with 8 environment skips on macOS.
- The new validation, approval-record and Chrome plugin copy behavior is covered by unit tests with synthetic trees, ACL blobs, interrupted refreshes and concurrent installs. No model-driven run was made and no desktop action ran on macOS for this release; setup and the harness fixtures ran only in disposable containers and isolated homes.
