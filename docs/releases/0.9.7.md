# LCU 0.9.7

**macOS fixes for computer use that stopped working after a ChatGPT update or a slow turn end, plus smaller fixes to `lcu apps` and update notices.** LCU now recovers from a stale Computer Use service left running by a ChatGPT update, a slow or failing macOS `turn-ended` command no longer breaks later calls, `lcu apps` skips unreadable app bundles, and a new release is announced at most once a day per account. Everything else is as in [0.9.6](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/releases/0.9.6.md). Windows remains deferred.

## Changes

- **Stale Computer Use service after a ChatGPT update** ([#26](https://github.com/amontlabs/lcu/pull/26)). On macOS, a `SkyComputerUseService` started from the previous ChatGPT version can keep the socket lock after the app updates while refusing every client, so every call failed with `Sky Computer Use native pipe startup failed` (seen once, for about 4 minutes, on the update from 26.930.21537 to 26.930.61225). On exactly that error, LCU now looks for one service of your own that started before its bundle was replaced, runs from the ChatGPT Sky bundle or `$CODEX_HOME/computer-use`, is the only holder of the socket lock and fails `codesign --verify` against the code on disk. If every check still holds when re-checked just before acting, it sends that one process SIGTERM, waits up to 3 s and retries the call once. It never sends SIGKILL, never signals the same instance twice, and does nothing with a custom socket path or a `HOME` other than the account's home. When any check is inconclusive, the original error is returned unchanged. Docs: [troubleshooting](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/INSTALLATION.md#native-pipe-startup-failed-after-a-chatgpt-update), [adaptations](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/STANDALONE-ADAPTATIONS.md).
- **Slow macOS `turn-ended` command** ([#24](https://github.com/amontlabs/lcu/pull/24), [#23](https://github.com/amontlabs/lcu/issues/23)). The signed `SkyComputerUseClient turn-ended` command was reported to take about 5.2 s, so LCU's 3 s limit killed it every turn, and the failed step was retried before every later Sky request in that MCP process, which then failed too. The command now gets 10 s and runs in the background (the next Sky request waits for it), a slow or failed run is logged with its elapsed time, exit code and stderr, and a failed command is retried once at the next request and then dropped with one warning. It never fails a Sky request. #23, listed as open in 0.9.6, is addressed here. Record: [turn-ended run](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/verification/turn-ended-cli-timeout-2026-10-07.md).
- **`lcu apps` and malformed `Info.plist`** ([#28](https://github.com/amontlabs/lcu/pull/28), [#27](https://github.com/amontlabs/lcu/issues/27)). An app bundle whose `Info.plist` is not well-formed XML (for example a Steam shortcut ending in NUL bytes) made `lcu apps` exit with an `ExpatError`. Such a bundle is now skipped like any other unreadable one, in listings and in `allow`/`revoke` name resolution.
- **Update notices once a day** (`d99d05f`). Each new Claude Code or Codex session was told about the same release again. A release is now announced at most once every 24 hours across the account, each session still at most once, and a newer release at once. The `lcu-approve` mod uses the same rule through `lcu update --notice --json --announce=<session>`. `lcu status`, `lcu doctor`, `lcu update --check` and a plain `lcu update --notice` still always show the notice. Docs: [update notices](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/INSTALLATION.md#update-notices).
- **Refresh stamp and clock skew** ([#29](https://github.com/amontlabs/lcu/pull/29)). A refresh stamp written a few milliseconds "in the future" (seen as an intermittent Windows CI failure) was treated as invalid and started a second background refresh. Up to 2 s of negative age now counts as fresh; a stamp further in the future is still reclaimed.

The original runtime, tool schemas and instructions are unchanged; LCU's own macOS host and Sky wrapper changed in #24 and #26. No new tested app pairs are claimed.

## Gates

- `npm test --prefix adapters` on macOS: 131 tests, 123 passed, 8 skipped (installed Pi and Windows), none failed.
- `python3 -m unittest discover -b -s tests -p 'test_*.py'` on macOS: 743 tests passed, 1 skipped (the plugin hook's missing-Python case, because this host has a qualifying Python in `/opt/homebrew/bin`). New tests cover the stale-service checks and recovery (with fakes only; no real process is signalled), the slow, failing and retry-once `turn-ended` cases, the malformed `Info.plist`, the account-wide notice cooldown and the clock-skew stamp.
- `tests/run.sh linux/arm64` (native, original sandbox required in the read-only gate) against the pinned official ChatGPT 26.915.31945 package: 743 Python tests (24 skips: the 18 plugin hook tests, which need `shasum`, and 6 environment skips), offline in-place installation, agent registration, the original GTK desktop suite, the adapter-path, GTK 4, controls, sandbox and hung-engine suites, and the read-only mount gate all passed.
- `tests/run.sh linux/amd64` (emulated; the original sandbox cannot be required there) passed with the same suites.

## Not verified

None of these changes was observed on a real desktop as a release: the stale-service recovery during a live ChatGPT update (on the macOS verification guest or elsewhere), including the exact `codesign` output and kernel-reported executable of a stale service; the slow `turn-ended` path live (on the maintainer's Mac the signed command finished in about 0.1 s, so the 10 s allowance, background run and retry-once-then-drop were exercised with fake clients only), and cursor removal; `lcu apps` with real Steam shortcuts on macOS; the notice cooldown across real Claude Code and Codex sessions; and the clock-skew fix on Windows beyond its CI job. Everything listed under "Not verified" in [0.9.6](https://github.com/amontlabs/lcu/blob/v0.9.7/docs/releases/0.9.6.md) still applies, except that #23 is now addressed.
