# LCU 0.7.0

This release makes LCU deliver instructions to the model exactly as official Codex computer use does. Official Codex wires computer use through the bundled `unified-computer-use` plugin: the original `cua_repl` MCP server and its lifecycle hooks, with no skill. The model gets the original initialization instructions, tool descriptions and tool results, including the full guide returned by the first call. LCU now registers no skill either. It adds no new platform or harness verification claims; Windows remains deferred.

## Changes

- **No LCU skill.** LCU 0.6.0 and earlier registered an LCU-authored `lcu` skill that told the model to read copied guides before its first call, and setup copied those guides into each account. Neither exists in official Codex. In a benchmark on macOS, the mandatory reading cost time and tokens on every run, and Codex tried to open the skill file before working, even after the reading step was removed. Setup now registers no skill and copies no upstream documents. See [instruction delivery](../INSTRUCTIONS.md).
- **Upgrade cleanup.** Setup removes the `lcu` skill registered by earlier versions for the selected harness and scope, and deletes the generated copy under `~/.local/share/lcu/skills`. It removes the skill only after confirming the installed `SKILL.md` is LCU's own, and removes it for every agent so the shared `.agents/skills` copy goes too.
- **OMP and Hermes** packages contain no skill. Hermes injects only the original initialization instructions and tool descriptors each turn.
- **Exports** carry no skill. The Codex plugin export mirrors the original plugin manifest without adding a skills entry.
- **Archives** no longer ship `skills/lcu`.

## Verified instruction parity

On macOS with ChatGPT 26.928.20755, the official plugin server and LCU's Codex and Claude Code relays returned byte-identical MCP initialization instructions and a byte-identical first-call guide (19,774 characters). The `js` tool description differs only in its browser section, because LCU's default surface is computer-only; the in-app browser and MCP Apps backends exist only inside the ChatGPT app, and Chrome stays opt-in.

## Gates

- `tests/run.sh` passed in disposable Linux ARM64 (native) and AMD64 (emulated) containers: 239 Python tests, offline installation from the prepared official-app fixture with acquisition network disabled, agent registration with no skill installed, the exported MCP contract run as the target account, and the original GTK desktop suite.
- The adapter suite passed 36 tests with 8 environment skips. Isolated OMP and Hermes registration tests and the OMP host tool-call test passed against the installed OMP and Hermes on macOS.
- The macOS archive installed with `--offline --runtime-only` into a disposable prefix on Apple Silicon, reusing signed ChatGPT 26.928.20755 (CUA `0.0.27/20260927214556-b77d38801cca`) in place; `--version`, `doctor`, `doctor --help` and `prune` passed. Setup from it removed an `lcu` skill registered by the previous version from Codex and Claude Code projects, including the shared `.agents/skills` copy.
- On that Mac, one model-driven desktop task each through Codex CLI + LCU and Claude Code + LCU completed the Finder, TextEdit and Calculator steps with an independent file check. Codex made no attempt to read a skill file. This is a smoke check, not new platform evidence.
