# LCU 0.11.4

**The Claude app now flags a session that is waiting for a Computer use approval.** In the Claude desktop app's Code tab, the `lcu-approve` mod asks the per-app approval with the engine's own question card instead of a side pane, so the app marks the session as needing input and notifies you.

## Changes

- **Computer use approval is a question card in the Claude app.** The app flags a session as needing input only for a permission request, which the engine's question card is and a mod pane is not, so an approval shown as a pane in the Code tab could go unnoticed. When the session runs in the Claude app, the mod (now 0.5.0) asks with the question card: "Computer use will be able to see and control Zed (dev.zed.Zed). Allow it?", with Allow this conversation, Always allow (when the runtime offers it) and Deny. A high-risk request starts with "⚠️ High risk —" and puts the runtime's warning before the question. Terminals keep the **Computer use approval** pane, and the narrow-terminal and headless paths are unchanged. The mod's tests also load again on Claude Code 2.1.295 ([details](../ADAPTERS.md#native-app-approvals-in-claude-code-and-the-claude-app)) ([2413e94](https://github.com/amontlabs/lcu/commit/2413e94)).
- **App icons from asset catalogs show again in the approval pane (macOS).** For apps without an `.icns` file, such as UTM, the icon drawn by the system was saved as TIFF instead of PNG and then dropped, so the pane showed no icon. It is now converted to PNG ([fef3f73](https://github.com/amontlabs/lcu/commit/fef3f73)).

## Behaviour changes to know about

- **Claude app approvals are in the chat, not the side pane.** The question appears as a card in the conversation. The app draws that card itself, so it shows only the question text and the three choices: no app icon and no "High risk" badge (the warning is in the question text instead).
- **Dismissing the card counts as a cancel.** Closing or skipping the card records `cancel`, the same as Esc on the pane, and the app is not controlled.
- **Not yet driven live.** The mod's question-card path is covered by Claude Code's test kit. That a question card flags the session in the Claude app was observed on 2026-10-14 with a test mod; the shipped mod itself has not been driven in the app.

## Upgrading

Run `lcu update`, then restart your agents. Your agent registrations and saved choices carry over, and `lcu update` refreshes the user-scope `lcu-approve` mod; for a project-scope mod, rerun `lcu setup --agent claude-code --scope project` in that project. To go back, reinstall 0.11.3.
