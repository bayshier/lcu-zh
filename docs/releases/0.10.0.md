# LCU 0.10.0

<!-- lcu-severity: breaking -->

**LCU no longer needs Python.** Install, setup, launch, the Chrome relay and `lcu update` now run on the Node that ships inside the ChatGPT app. You need nothing installed beyond the official app and your agent. Computer use itself is unchanged: LCU still hands over to the app's original runtime.

This release is marked breaking because error and help messages are worded differently and the exit status after a signal changed. If you have scripts that parse either, check them after upgrading.

## Changes

- **No Python.** Python 3.12+ is no longer a prerequisite. On Linux the installer no longer installs `python3` or `libxres1`, and the Claude Code plugin no longer looks for Python before installing LCU ([#31](https://github.com/amontlabs/lcu/pull/31)).
- **LCU uses the app's own Node.** Each release records the path of the ChatGPT app's Node, and the `lcu` commands are small shell scripts that run it. If the app is moved or removed, `lcu` tells you to repair the app or reinstall LCU.
- **Setup follows `$HOME`.** Without `--user`, `lcu setup`, `lcu status` and `lcu update` now use `$HOME` when it is a valid folder you own, so `HOME=<folder> lcu setup` configures that folder instead of your account's home. Root still needs `--user`. On macOS, setup warns you when the folder isn't your account home, because the ChatGPT helper is only found there by default.
- **Claude Code stops cleanly.** When Claude Code is killed or interrupted during an action, LCU now exits within a few seconds. Before, it could keep running for up to a minute and then crash.
- **Quieter Pi, OMP and Hermes.** Background messages from the computer-use runtime no longer appear in these agents' input area ([#30](https://github.com/amontlabs/lcu/issues/30)).
- **Safer installs and updates.** `lcu update` checks the downloaded release before and after unpacking it, and uses `curl` when you're behind an HTTPS proxy. `install.sh` refuses files writable by others or owned by another account, and `install.sh --help` works before the app is installed.
- **Waiting is visible.** When another LCU process holds a lock for more than a second, LCU now says `LCU: waiting for another LCU process to release …`.
- **Faster startup on Linux.** `lcu --version` starts in about half the time of 0.9.7. On macOS startup is about the same, since most of it is spent checking the app's signature.

## Behaviour changes to know about

- **Messages.** Errors still look like `LCU: <message>` with exit status 1. A usage error is now one line naming the command and pointing to its `--help`, with exit status 2, and help texts start with `Usage:`. Commands and flags are unchanged.
- **Exit status after a signal.** On macOS, when the server `lcu` waits for is ended by signal N, `lcu` now exits with 128 + N, the shell convention. 0.9.7 used 256 − N.
- **Chrome relay file.** The private relay copy under `~/.local/share/lcu/browser/<id>/` is now `lcu-native-host.mjs` instead of `lcu-native-host.py`. The browser manifest still points at `lcu-native-host`, and `lcu update` replaces the old file for you.

## Upgrading

Run `lcu update`, then restart your agents. Your agent registrations and saved choices carry over. To go back, reinstall 0.9.7.
