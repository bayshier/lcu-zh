# LCU 0.11.3

**`type_text` no longer drops accented letters, Korean or emoji on macOS.** Computer Use typed each character as one key of the active keyboard layout and silently skipped any character that layout has no key for.

## Changes

- **Text your layout cannot type now arrives whole (macOS).** The defect is in OpenAI's signed helper ([openai/codex#27494](https://github.com/openai/codex/issues/27494)): Korean syllables, emoji, and `ñ` on French AZERTY were dropped while the call still reported success. When `type_text` gets text with a character above U+007F, LCU now splits it at control characters. Return, Tab and other control characters are still typed, so they still submit a form and move focus. Each chunk between them that contains such a character goes whole to the original `paste` as plain text; the other chunks are typed. ASCII-only text, explicit `paste` and other calls are unchanged. The fix ran live in Safari on ChatGPT 26.1007.30912 with French AZERTY, and the same routed calls were checked by hand in TextEdit and VS Code ([record](../verification/macos-unicode-input-2026-10-12.md)) ([#41](https://github.com/amontlabs/lcu/issues/41), [#42](https://github.com/amontlabs/lcu/pull/42), thanks @entelecheia, who reported the problem and wrote the fix, including the root-cause analysis).
- **A list of upstream workarounds.** [UPSTREAM-WORKAROUNDS.md](../UPSTREAM-WORKAROUNDS.md) lists each LCU workaround for an OpenAI defect, with its upstream issue and when it will be removed.
- **ChatGPT 26.1007.30912 is a tested pair on macOS.** With CUA runtime 0.0.29 on Apple Silicon, the installed-app and desktop checks passed ([record](../verification/macos-chatgpt-26.1007-2026-10-12.md)), so `lcu doctor`, `lcu status` and `lcu setup` no longer warn that it is untested.

## Behaviour changes to know about

- **Pasted text is slower.** Each pasted chunk takes about 150-200 ms instead of about 15 ms of typing, and about 2 s in VS Code and in fields that block paste.
- **Pasted text is briefly on the clipboard.** Clipboard managers can see it. The original paste then restores your previous clipboard, unless something else wrote to the clipboard in that moment.
- **Fields that block paste get nothing.** A field that refuses paste silently inserts nothing for those chunks, with no error.
- **Once-scoped approvals ask per chunk.** Each typed or pasted segment goes through the app's approval. Approvals for the session or always are per app and still ask once.
- **Not handled yet.** Non-Latin layouts (such as Russian) and input methods are not handled; ASCII typed there can still be dropped.

## Upgrading

Run `lcu update`, then restart your agents. Your agent registrations and saved choices carry over. To go back, reinstall 0.11.2.
