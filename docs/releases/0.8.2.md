# LCU 0.8.2

This release fixes computer use on Linux machines where the original Node REPL can sandbox its children, and records why GTK 4 windows ignore window-targeted keys and clicks. It adds no new harness verification claims and no new tested app pairs; Windows remains deferred.

## Changes

- **Linux: computer use works where the original sandbox is active.** On a machine with bubblewrap and user namespaces, the original `node_repl` ran Sky under a network-disabled `codex sandbox` unless the host sent `codex/sandbox-state-meta`. Its seccomp filter refused the connection to the X11 socket, so every `js` call failed with `Could not connect to X11 ... Operation not permitted` while `lcu doctor` passed. None of LCU's adapters (Codex relay, Claude relay, Pi, Oh My Pi, Hermes) or generic MCP clients send that metadata, so all of them were affected. `lcu` now adds the same disabled sandbox state official Codex sends under `danger-full-access` to the original `NODE_REPL_REQUEST_META` on Linux. A host that sends its own `codex/sandbox-state-meta`, per call or in that variable, keeps precedence, so a deliberately stricter profile is honored. `LCU_NODE_REPL_SANDBOX=host` declines the default. Original approvals are unchanged. See [Linux sandbox state](../ADAPTERS.md#linux-sandbox-state).
- **GTK 4 input is documented, not changed.** The original engine delivers window-targeted keys and coordinate clicks with `XSendEvent`, which GTK 4 (XInput2 only) ignores; AT-SPI actions, `typeText` and `paste` work, and desktop-level `sky.press_key`/`sky.click` after `sky.activate_window` reach GTK 4. LCU adds no input implementation. The [verification note](../verification/linux-sandbox-and-gtk4-input-2026-10-02.md) lists the session requirements.
- **Tests.** The Docker gate now runs the GTK oracle flow through a bare client, the Codex relay, the Claude relay, the shared Pi/Oh My Pi client and the Hermes bridge with no sandbox metadata, in a container where the sandbox is active (negative control included), and adds a GTK 4 fixture. `tests/codex_sandbox_state.py` records what a Codex CLI sends under each sandbox mode.

## Gates

- `tests/run.sh` passed in disposable Linux ARM64 (native) containers against the official ChatGPT 26.928.31416 and 26.915.31945 packages, and in AMD64 (emulated) containers against the same two: 312 Python tests, offline in-place installation, agent registration, the exported MCP contract, the original GTK desktop suite with its independent save oracle, the new adapter-path suite (bare client, Codex relay, Claude relay, shared Pi/Oh My Pi client, Hermes bridge, no sandbox metadata), the GTK 4 input check, and the read-only mount gate. The read-only gate on ARM64 ran with bubblewrap allowed (`seccomp=unconfined`, `apparmor=unconfined`, `SYS_ADMIN`) and required the original sandbox to be active, with the negative control and the stricter-host-profile check. Under emulation bubblewrap cannot start, so the sandbox could not be required on AMD64 there.
- Native x86-64: on an Ubuntu 24.04 host with native Docker, the same release archive's desktop suite (GTK suite, adapter paths with the sandbox required, GTK 4 check) passed as the unprivileged account against both packages with the same container flags. That host's full `tests/run.sh` also fails the exported-MCP registration step for 0.8.1 (`failed to start Node runtime: Permission denied`), so it was not used as the AMD64 gate; the cause is not in LCU's changes and was not investigated.
- The unfixed 0.8.1 runtime fails the unmodified GTK suite under the same sandbox-enabled container flags with `Could not connect to X11 ... Operation not permitted`, the reported error.
- The adapter suite passed 36 tests with 8 environment skips on macOS. `tests/codex_sandbox_state.py` ran against Codex CLI 0.159.1 in an isolated home with a scripted provider; its results are in the [verification note](../verification/linux-sandbox-and-gtk4-input-2026-10-02.md).
- No model-driven run was made and no desktop action ran on macOS for this release; the macOS archive installed with `--offline --runtime-only` into a disposable prefix (`--version`, `status --json`). Setup and the harness fixtures ran only in disposable containers and isolated homes.

## Correction (added with 0.8.3)

The GTK 4 bullet above says `typeText` works. That depends on the engine: ChatGPT 26.928.31416 inserts into a GTK 4 entry through AT-SPI (in some runs the first call to a freshly started app inserted nothing and later calls inserted), while 26.915.31945 returns success without inserting anything. Where it inserts nothing, activate the window and use the desktop-level `sky.type_text`. 0.8.3 also makes window-targeted keys, clicks, scroll and drag work on GTK 4; see the [0.8.3 notes](0.8.3.md). The sandbox default described above has a security consequence this note did not state: the original `node_repl` JavaScript kernel runs without the sandbox on Linux; see [Linux sandbox state](../ADAPTERS.md#linux-sandbox-state).
