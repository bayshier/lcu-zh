# LCU 0.8.4

This release fixes seven defects that a review found in 0.8.3's Linux window-targeted input translation. It adds no new harness verification claims and no new tested app pairs; Windows remains deferred.

## Changes

- **Concurrent requests no longer type into the wrong window.** The translation planned a request before queuing it, from a focus snapshot that a still-running request could invalidate: requests to window B and then A could send A's key to B. Planning, activation and a final focus check now run inside the queue, and if the focus is not on the target immediately before input is sent, the call fails with an error and sends nothing.
- **Key holds are always released.** A translated `key_down` could leave the desktop key held when the target closed or minimized before `key_up`, and overlapping holds of one key (two windows holding Shift) released each other. Holds are now owned per (window, chord), always released at the desktop level, and the key is released only when its last owner lets go.
- **Stale coordinates are refused.** A click, scroll, move or drag start whose point lies outside the target window's current bounds now fails with an error instead of clicking whatever application is at that place on the desktop. A drag may still end outside the window.
- **Pointer input to a window with a modal dialog is refused.** Keyboard input still goes to the dialog; for clicks, scrolls, moves and drags the parent's coordinates do not describe the dialog, so the error names the dialog and asks to target it explicitly.
- **A caller-supplied `NODE_REPL_TRUSTED_SERVICES` is kept as given.** An empty or custom-only map used to gain LCU's `sky` entry. LCU now adds its wrapper only when no map is supplied, or replaces an explicit entry that names the original Sky service.
- **The toolkit cache survives neither PID reuse nor foreign clients.** The cache is keyed by (PID, process start time) and revalidated; a window whose `WM_CLIENT_MACHINE` is not this host, or whose process is in another PID namespace, is left to the original service because its `_NET_WM_PID` does not name a local process.
- `LCU_LINUX_INPUT_TRANSLATION=off` and the per-pair `native_input` switch are unchanged. See [Linux window-targeted input](../ADAPTERS.md#linux-window-targeted-input) and the [verification note](../verification/linux-input-translation-2026-10-02.md#084-review-findings-fixed).

## Gates

- `tests/run.sh` passed in disposable Linux ARM64 (native) containers against the official ChatGPT 26.915.31945 (the pinned package) and 26.928.31416 packages, and in AMD64 (emulated) containers against the same two: 325 Python tests (3 environment skips), offline in-place installation, agent registration, the exported MCP contract, the original GTK desktop suite with its independent save oracle, the adapter-path suite, the GTK 4 window-targeted suite (now also a hold released after its window closed, refused pointer input to a modal parent and an out-of-bounds click refusal), the controls suite, and the read-only mount gate. The ARM64 read-only gate ran with bubblewrap allowed and required the original sandbox to be active, with the negative control and the stricter-host-profile check; under emulation bubblewrap cannot start, so the sandbox could not be required on AMD64. 26.915.31945 has no `key_down`/`key_up`, so the held-key checks run only against 26.928.31416.
- Native x86-64: on an Ubuntu 24.04 host with native Docker, the release build of the x64 archive ran the read-only mount gate with the original sandbox required (the desktop suites as the unprivileged account) against both packages; both passed. As for 0.8.3, that host's full `tests/run.sh` was not used. The run used a temporary directory and a throwaway image and volumes, all removed; no installed application, VM or user data on that host was touched.
- The new wrapper logic is covered by `adapters/test/linux-sky-service.test.mjs` (19 in-memory tests against a fake desktop; 14 failed against the 0.8.3 logic before the fixes, 19 pass now) and `node --test adapters/test/*.test.mjs` passes (55 passed, 8 environment skips, 0 failed). The two new `tests/test_runtime.py` cases cover empty, custom-only and explicit original-Sky service maps.
- The macOS archive installed with `--offline --runtime-only` into a disposable prefix and home (`--version`, `status --json`); no desktop action ran on macOS and no model-driven run was made for this release. Fractional scaling, other window managers, real Chrome or Electron applications and a window from a genuinely remote X client were not exercised; the foreign-client rule is covered only by the in-memory tests.

## Correction (added with 0.8.5)

The "Key holds are always released" item above overstated the fix. Wrapper-side hold bookkeeping still left modifiers stuck after partial chord releases, key aliases such as `Shift` and `Shift_L` bypassed the owner counts, a failed release lost its retry routing, turn cleanup did not release holds, and focus-changing calls such as `activate_window` and pass-through fallbacks bypassed the queue. The "foreign clients" item trusted `_NET_WM_PID` too far: a client sharing the X server from another PID namespace can advertise an id that collides with a local process. 0.8.5 stops translating `key_down` and `key_up`, queues every focus- or input-changing call, and confirms the window's process with the X server. See the [0.8.5 notes](0.8.5.md).
