# LCU 0.10.1

**Faster host starts, and Pi and OMP no longer stall at the end of a turn.** Starting a computer-use host no longer runs the app's full signature check every time on macOS, or hashes the whole app copy every time on Windows. Computer use itself is unchanged.

## Changes

- **No more `LCU turn cleanup is pending` after a slow start in Pi and OMP.** When a host took more than 60 s to start, which happens when many sessions start at once, the connection failed with `MCP error -32001: Request timed out`. Pi and OMP then started a second host only to end the turn, which could wait another 60 s and show the warning, even for turns that never used computer use. They no longer start a host to end a turn that no host has seen ([#32](https://github.com/amontlabs/lcu/issues/32), [#33](https://github.com/amontlabs/lcu/pull/33), thanks @valkyriweb).
- **More time for a host to start.** All agents now wait up to 120 s for a host to start and list its tools, instead of 60 s. That is the same limit LCU already used for ending a turn ([#33](https://github.com/amontlabs/lcu/pull/33)).
- **Faster starts on macOS.** LCU checked the app's full signature (`codesign --verify --deep`) on every host start. It now does so once per app build, remembers the result in `~/Library/Caches/lcu/macos-signatures.json`, and hosts starting together share one check. Every start still confirms the app is signed by OpenAI. On one Mac, a single start went from about 1.5 s to 0.22 s, and 16 starts at once from a median of 9.25 s to 0.75 s ([#35](https://github.com/amontlabs/lcu/pull/35)).
- **Windows: the app copy is hashed once.** The Windows candidate no longer hashes every file of LCU's private copy of the ChatGPT app on every host start. It hashes the copy once, records each file's size, modification time and identity in `%LOCALAPPDATA%\LCU\cache\windows-inventory.json`, and later starts only compare those. This was not measured on Windows ([#36](https://github.com/amontlabs/lcu/pull/36)).

## Behaviour changes to know about

- **Full checks still run where you'd expect.** Install, `lcu update`, `lcu setup`, `lcu doctor`, `lcu status`, `lcu --version` and `lcu browser` keep the full check, and so does the first host start after the app changes. A full check also refreshes the record, so the next start is fast.
- **What a start no longer catches.** An edit inside the app (macOS) or its private copy (Windows) that changes none of the recorded values is not detected when a host starts. The app normally changes only through its updates, which change them. `lcu doctor` still catches such an edit.
- **Two new cache files.** LCU writes `macos-signatures.json` or `windows-inventory.json`, with a `.lock` beside it, in its per-account cache folder. Deleting them is safe; the next start runs a full check.

## Upgrading

Run `lcu update`, then restart your agents. Your agent registrations and saved choices carry over. To go back, reinstall 0.10.0.
