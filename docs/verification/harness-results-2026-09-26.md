For both pinned Codex CLIs, the probe loaded that app's original MCP configuration (`enabled_tools` includes `js`, `js_reset`, and `turn_ended`) and installed the original Stop hook in a disposable Codex home. The actual provider request exposed only `js` and `js_reset`; after each normal JavaScript turn, the CLI called the model-hidden `turn_ended` through the relay with the same session and turn IDs observed on the original call. The relay also filters `js_add_node_module_dir` from model tool discovery. This records an intentional model-visibility adaptation, not full `tools/list` parity.

Claude Code made a separate schema-constrained title metadata request without tools. The local provider returned a valid synthetic title for that request; each case then asserted exactly one tool-call request and one result request. This metadata exchange is not counted as an extra original MCP invocation. The guarded `clod` wrapper ran in a real TTY; the literal `START CLAUDE` confirmation was typed. The test used an isolated HOME with only the onboarding fields `hasCompletedOnboarding` and `lastOnboardingVersion` set, the exact installed Claude binary symlinked into that HOME, a fake API key, and a local provider URL. Telemetry and error reporting were disabled using the documented Claude Code environment variables ([official reference](https://code.claude.com/docs/en/env-vars)).
