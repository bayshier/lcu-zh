# Hermes Agent harness integration

As of 2026-09-28, Hermes Agent's latest stable release is [v2026.9.24](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.24), package version 0.21.5, published 2026-09-24. The official tag object `e3dd27ee2d8b011737a4eea8e3eb3d711ab78690` dereferences to source commit `f97608f178d1ffeca59860195ab7da295f7c8e5f`. An isolated host installation from this release reported `Hermes Agent v0.21.5 (2026.9.24)`. No personal Hermes profile or credential file was used.

## Upstream interfaces

Hermes documents MCP servers as stdio or HTTP integrations in [`~/.hermes/config.yaml`](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp). Its native [Python plugin API](https://hermes-agent.nousresearch.com/docs/user-guide/features/plugins) exposes tools, skills, hooks, and middleware. Source at the official [v2026.9.24 tag](https://github.com/NousResearch/hermes-agent/tree/v2026.9.24) confirms the handler identity boundary: `model_tools._execute_tool` passes `task_id` and `session_id` to a plugin handler, but not `turn_id` or `tool_call_id`. Hermes' `agent/tool_executor.py` wraps the actual dispatch in its public `tool_execution` middleware with exact IDs from `tool_hook_ids(agent, task_id, call_id)`, and `hermes_cli/middleware.py` invokes `next_call` inside that middleware frame. LCU uses a `ContextVar` scoped to this callback to carry the exact identity to the registered handler and resets it with the middleware token. Parallel executions retain isolated contexts. Without that boundary, the real Hermes model flow was rejected before any computer-use request reached LCU.

LCU therefore installs an opt-in native Hermes plugin. Its model-visible `js` and `js_reset` tools are backed by the original runtime through the shared `adapters/client.mjs` MCP SDK client in a persistent Node bridge. The bridge forwards original tool descriptions, initialization instructions, call results, and exact session/turn/tool-call metadata. The plugin injects the generated LCU skill and original context before each model turn, and forwards turn finalization as original `Stop` or `Interrupt` cleanup. The plugin retains failed cleanup identities and retries them before enabling a later turn. A single Hermes process may own only one live CUA session at a time; switching to another sequential session closes and reconnects the runtime to clear its JavaScript state. Concurrent sessions fail closed.

Hermes' native approval selector is the existing host UI seam. At the official tagged source, [`prompt_dangerous_approval`](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/tools/approval_prompt.py) returns the user's exact `once`, `session`, `always`, `deny`, timeout, or cancellation choice. The CLI registers its TUI callback per thread through [`set_approval_callback`](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/tools/terminal_tool.py); LCU passes that callback explicitly because MCP elicitation runs off-thread. For original CUA app approvals, LCU offers session/permanent only when the original `_meta.persist` lists those scopes, then returns the selected scope in the original MCP response `_meta.persist`. For original browser-origin approval, LCU uses Hermes' same selector but only offers once or deny. LCU writes no Hermes allowlist or grant cache. Gateway/API sessions use Hermes' existing approval queue with the same scope flags and forward its returned choice; missing listeners fail closed. Unsupported elicitation forms, fields, metadata, malformed origins, and URL-mode requests are canceled. Host timeout or cancellation maps to MCP `cancel`; `deny` maps to `decline`. Hermes' current TUI labels Esc/Ctrl+C as denial.

Text and error-only results retain their original MCP result envelope, including `isError`. For image results, the adapter preserves the original bytes in Hermes' native `image_url` content part without resizing or re-encoding; the text fallback reports the MIME type rather than duplicating base64. Audio blocks are saved byte-for-byte through the shared `audio-files.mjs` helper and returned as local paths, matching LCU's other harnesses. Unsupported image-containing block kinds fail closed rather than being flattened into invented text.

## Verification

`tests/test_hermes_harness.py` exercises the plugin against a generated stdio MCP fixture. It checks descriptor and instruction delivery, generated-skill registration, exact LCU turn metadata, once/session/always/deny/cancel mapping, browser-origin one-time approval, gateway choice forwarding, fail-closed unsupported form elicitation, exact image bytes, audio file bytes, cross-session exclusion, and retry after a failed `Stop` cleanup. It runs the fixture beside the adapter dependencies from the built LCU release, so source checkouts do not need checked-in `node_modules`.

`tests/hermes_approval_tui.py` exercises the full Hermes TUI callback path through the installed CLI, LCU plugin, shared MCP SDK bridge, and generated stdio MCP fixture. A scripted loopback-only provider sends a deterministic `js` tool call; each case uses fresh temporary `HOME` and `HERMES_HOME`, the generated LCU skill, and no real provider key or desktop. The official Hermes v0.21.5 (2026.9.24) TUI passed seven cases: once returns `accept` without persistence metadata; session and always return the corresponding `_meta.persist`; explicit Deny returns `decline`; no response until the configured two-second timeout returns `cancel`; a request offering only session never displays the permanent option and returns session when selected; Ctrl+C follows Hermes' displayed denial behavior and returns `decline`. Every case observed the selector and an LCU `turn_ended Stop` lifecycle call. Evidence is stored outside the repository at `/private/tmp/lcu-hermes-approval-tui-evidence/`.

The latest official Hermes CLI passed `hermes plugins doctor lcu-cua --ci` with a fresh temporary `HOME` and `HERMES_HOME`; doctor confirmed runtime discovery, manifest parsing, import, and two tool/two hook registrations with no capability warnings. The manifest also declares its `tool_execution` middleware. `python3 -m unittest tests.test_hermes_harness -v` passes two focused adapter tests covering middleware identity, cleanup, approvals, multimodal responses, and session isolation.

The reusable opt-in runner is [`tests/hermes_real_desktop.py`](../../tests/hermes_real_desktop.py). It starts with a fresh Hermes profile, invokes the registered native plugin, restricts tools to `lcu_cua`, uses a loopback OpenAI-compatible proxy with the synthetic key `local-fixture-proxy`, and queries only a generated Linux GTK fixture through `docker exec`. It writes structured evidence when `LCU_TEST_EVIDENCE` is set. With `LCU_TEST_TOOL_SEARCH=off`, Hermes 0.21.5 (2026.9.24) used model `glm-5.3-flash`, session `20260928_124036_43d583`, and made five direct `js` calls. The model entered marker `hermes-lcu-7515fa9cf4c4` in the generated `LCU Target` window and clicked Save draft. The independent container oracle read that exact marker from `Target.txt`; `Other.txt` remained absent. Hermes exited 0.

A second run used the runner's `LCU_TEST_TOOL_SEARCH=on` setting against a clean HEAD plus the Hermes source changes. Hermes exercised its progressive-disclosure tools (`tool_search`, `tool_describe`, `tool_call`), which dispatched six original `js` calls through LCU. The generated Target oracle contained exact marker `hermes-lcu-ed6be2c61580`, Other remained absent, and the Hermes session was `20260928_124353_8aa4c2`. This validates the default wrapped route as well as direct tool registration. Both model runs used the macOS host with an isolated Linux ARM64 GTK fixture running LCU 0.4.2, ChatGPT 26.915.31945, and CUA 0.0.16. The container had no network, host home, credentials, or desktop mount. These runs prove Hermes-to-LCU GTK actions on that Linux fixture; they do not prove macOS desktop control or image/audio interpretation by a model provider.

The clean-source `tests/run.sh linux/arm64` gate passed with the Hermes change set: 199 Python tests, offline installation, all agent registrations, and the complete original GTK fixture suite. The built archive is `/private/tmp/lcu-harness-latest-20260928/committed-source/.verification/arm64.8l6xS9/lcu-0.4.1-linux-arm64.tar.gz`. This uses clean HEAD version 0.4.1; unrelated working-tree changes that bump the package to 0.4.2 are excluded.
