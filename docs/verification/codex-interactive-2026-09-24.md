## Native task

The natural-language request asked Codex to use LCU to set the `LCU Target` GTK draft to `Codex saved this generated fixture`, save it and leave `LCU Other` alone. Codex read the generated Linux skill and original guidance, called the original `js` tool repeatedly, inspected accessibility output, typed into Target and activated Save. The independent fixture oracle found `Target.txt` with the exact requested text and no `Other.txt`. The desktop and fixture had no network access. The earlier scripted/native model run documented in [adapter status](../ADAPTERS.md) used temporary MCP configuration without the full generated skill; this run closes that specific instruction-delivery gap.

## Chrome task

The natural-language request asked Codex to open `http://127.0.0.1:8080/` with the original unified Chrome extension API, enter `Codex saved this browser fixture` in Message, click Save and verify the page. The project was registered with `lcu setup --chrome`; the installed official extension was discoverable in sandboxed Chrome 154. Codex read the generated Linux and Chrome references and called `lcu.js` with `cua.createBrowserTab("chrome", ...)`, then `tab.typeText`, `tab.click` and `tab.getAXState`. The host displayed the original site's exact origin approval, `http://127.0.0.1:8080`; the tester selected **Allow once**. The returned accessibility state reported `Saved`. Independently, the fixture server recorded `/save?text=Codex%20saved%20this%20browser%20fixture` with the official extension's `x-browser-agent` header. This is a model-driven extension action, unlike the earlier native Chrome-window fallback task. The test did not grant other origins or bypass the original policy.
