# Pi approval adapter check, 2026-09-26

Pi 0.73.0 needs its `select` UI primitive for empty-form approvals because `confirm` returns the same `false` value for a No choice and a dismissed dialog. The adapter now maps Allow to the original MCP accept response, Decline to decline, and dismissal or missing UI to cancel. It preserves the server's message and response shape and adds no permission cache.

The regression in `adapters/test/pi-approval.test.mjs` reproduces the dismissal ambiguity with `confirm() => false` and `select() => undefined`. It also checks browser-origin acceptance, decline, cancellation, headless cancellation, exact-origin preauthorization, a lookalike origin, and an unrelated empty-form request while an origin is preauthorized. `node --test adapters/test/pi.test.mjs adapters/test/pi-approval.test.mjs adapters/test/client.test.mjs` passed 13 tests. Pi's versioned [0.73.0 extension API](https://github.com/badlogic/pi-mono/blob/v0.73.0/packages/coding-agent/docs/extensions.md) documents the UI behavior.

A bounded Pi 0.73.0 TUI run used an isolated home, a local scripted provider, and the repository's official MCP SDK fixture. Pi displayed `Allow Browser use to access http://127.0.0.1:8080?` with Allow and Decline choices. Escape dismissed the first prompt and the fixture received `{"action":"cancel"}`; choosing Allow on a repeated prompt produced `{"action":"accept","content":{}}`. No browser, external service, or credential was used. The captured local run is under `/private/tmp/lcu-pi-origin-select-20260926/`; its disposable provider and Pi processes exited cleanly.

The supported approval inputs inspected for this work are original Mac native-app empty forms, opt-in external-Chrome origin approvals, and an unrelated empty-form browser-history approval. The original Mac runtime owns native permission reuse. The browser-origin request is recognized only for its exact marked origin; an origin allowlist does not accept unrelated approvals. No field-containing or URL-mode elicitation was found in these supported request paths. Conditional browser-auth credential entry belongs to a capability not exposed by the external-Chrome path, so it is not a demonstrated baseline omission. Pi continues to cancel unsupported schemas and URL mode.
